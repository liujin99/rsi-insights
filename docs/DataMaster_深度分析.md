# DataMaster（任务条件化自主数据工程）深度分析

**总表条目**：#153｜arXiv 2605.10906（v2 2026-05-13）｜T2 **[高价值]**（引用链补扫→**用户点名深读坐实**）｜深读批次⑰（2026-11-24，全文 HTML + 附录）

**【一句话】****「训练栈钉死、agent 只动数据侧」的第一份完整方法实现**（用户设定的正面形式化）：DataTree 红黑双节点搜索（红=发现外部数据、黑=清洗/适配/组配成可执行 DataLoader）+共享数据池+全局记忆+UCB 调度；MLE-Bench Lite 上**只动数据不动模型代码**把奖牌率 35.91%→68.18%（+32.27%），PostTrainBench 上从零发现数据把 1.7B base 平均分 8.47→31.17（GSM8K 9→49.43）——**消融显示全局记忆是生死件**（去掉它 overcome rate 69.96%→28.57%、增益全灭）。

## 2 机制（§3 三件套）
- **问题形式化**：任务 T+固定学习算法 a₀+初始数据状态 D₀+预算 B；D*=argmax E(T, a₀, D)——**data state（可执行数据配置）当一等优化对象**：可用源+所选/所组子集+把它们变成算法输入的处理逻辑。
- **DataTree 红黑双节点**：**红节点=数据探索**（生成搜索 query→开放网络检索→轻量筛选〔元数据/schema/模态/规模/标签结构/样本预览〕→写共享数据池，每条存 manifest）；**黑节点=数据开采**（从池里选源、调组成、清洗转换、构特征、适配固定训练接口→物化成 DataLoader→提交固定训练拿下游分 y_v+诊断 φ_v）。
- **全局记忆**：节点级记录（红：(red, ΔP, φ)；黑：(black, D, y, φ)）；默认检索上下文=父节点+兄弟节点记录，可主动跨查——树是**协同**的不是独立的（红避免重复发现、黑复用验证过的状态）。
- **生长+调度**：红节点后跟一小批并行黑节点；轻量外部控制器按最新训练反馈决定「深挖当前分支 vs 开新红节点」；UCB 式贪心调度 Score(v)=R/N+c_t√(log N_Par/N)（c_t 分段线性衰减）决定谁吃下一单位预算。

## 3 主结果核验（Table 1-4 逐行）
- **MLE-Bench Lite（Kaggle 任务，模型代码钉死）**：DataMaster 奖牌率 **68.18%**（初始 35.91%，+32.27）/金牌 **45.45%**（+22.72）；超 DatasetResearch 59.09、ML-Master 2.0 40.91、Claude Code 36.36、Codex 22.73。
- **PostTrainBench（1.7B base，12h，不给训练数据、自己找）**：平均 **31.17**（初始 8.47，+22.70）vs Codex 18.46/Claude Code 11.47/DataFlex 19.09；**GSM8K 9.02→49.43**、HealthBench Easy 0→34.93、HumanEval 8.53→43.29；**GPQA 31.02>人类 instruct 参照 30.35**（唯一单项超人，总分 31.17 vs 人 46.91 仍差 15.7）。
- **骨架消融（4 个前沿 LLM，§4.3）**：GLM-5/Claude-4.6-sonnet/Qwen3.5-Plus 都 ~30% 平均；**GPT-5.4 只有 14.64%**——每节点工具调用 11.3 次 vs GLM-5 的 40.7 次（**长程数据搜索吃工具调用密度，不吃模型名气**）。
- **组件消融（10 任务，Table 2）**：全开=奖牌 90%/金牌 80%/overcome 69.96%；**去记忆=50%/20%/28.57%（增益全灭）**；去红节点=内部精炼反而升（overcome 72.40%）但金牌掉 10%（外部发现有独特价值）；去黑节点=发现了数据没人适配（奖牌掉）。
- **成本结构（Table 4，981 节点）**：红 641 个/便宜（$0.021、21.3 分钟）、黑 340 个/贵 3 倍（$0.062、50.6 分钟）；红动作 Search 49.5%，黑动作 Bash/Env 51.8%——**红铺广度、黑花预算验证**，与设计自洽。
- **测试时扩展（§4.3）**：GPQA 18.75→31.02 随预算阶梯上升（找到 MedQA 等新数据源时跳变）——预算买到的是**新数据配置**不是更长执行。
- **抗弱起点（Table 3）**：Algo-only（只给算法骨架）起点更低（35.91 vs 45.45）但增益更大（+32.27 vs +27.28）——数据侧优化能补弱起点。

## 4 深读金子（摘要外）
- **金子① 全局记忆=生死件（本批最硬的消融）**：去掉记忆 overcome 69.96%→28.57%、金牌 80%→20%——**数据工程的价值大半不在单次决策而在「记住了什么」**（哪里搜过/什么变换试过/哪个 adapter 能用/什么数据涨分）。与 #151 共享记忆 +7.00% 互证成族：**这条线两篇独立工作把「结构化记忆」钉成数据中心 RSI 的第一杠杆**（一为树间教训、一为跨节点工件+结果记录）。
- **金子② 红/黑分工=探索/开采的成本分离**：红便宜广铺（找数据不训模型）、黑贵而深（组配+训练验证）——**发现与验证解耦成两类节点**，调度器再按 UCB 分预算。对姊妹库：代理粗筛（便宜广铺）→目标短训（贵而深）的**两档成本结构与 DataTree 同构**——用户的梯子方法论在这篇里有了正面原型。
- **金子③ 外部数据发现是一等动作**：PostTrainBench 设置下**池子都不给**（agent 自己上网找：GSM8K 49.43 主要来自发现的数学数据）——数据配方空间不只是「池内怎么配」，还包括「池子本身怎么扩」；对用户的 r-scan/固定池范式是**外扩维度提醒**（红节点=引入新域源）。
- **金子④ 泄漏三层协议**：源黑名单（基准页/讨论页/测试集名 URL）+测试集哈希去重+全量溯源（URL/时间戳/内容哈希）；GPQA 7,479 条审计**零精确/模糊匹配**（3-5gram 重叠 0.08-1.06%）——开放网络找数据场景的防污染纪律范本（连 #150 SHA-256+8-gram 协议）。
- **金子⑤ GPT-5.4 失败的机制注脚**：工具调用 11.3 vs 40.7 次/节点——**数据中心 agent 的瓶颈在「肯不肯动手跑工具」不在模型代际**（连 #152 推理档位诊断：effort 买数据构建深度）。
- **金子⑥ 训练侧信号自证**：测试时扩展的跳变全部对应「新数据源被整合」而非「同配置再训一遍」——**下游训练当唯一质量信号**（不用启发式数据质量分）这条设计选择被结果反证有效。

## 5 库内连线
- **#152 RSIBench-Data**：互补对——DataMaster 是**方法**、RSIBench-Data 是**尺**；都在 PostTrainBench 锚上（DataMaster 31.17 vs 尺子上 Sonnet-5 类 agent 的诚实读数可直接对表）；两者都吃「#100 PostTrainBench 交叉锚」。
- **#151 Gödel Forest**：记忆家族双证（金子①）；树搜索家族三作（Gödel Forest 多树+教训/DataMaster 单树+工件记忆/Curation-Bench 无树轨迹）。
- **#150 Curation-Bench**：池设定对照（固定池选/改 vs 开放世界发现+组配）；泄漏协议互证（金子④）。
- **#100 RSI-Prime**：同 PostTrainBench 锚——RSI-Prime 训 GLM-5.3 得 48.24（训「研究者」）vs DataMaster 用 GLM-5 骨架得 31.17（造「数据框架」）：**两条路线在同一把尺上的分差读数**（研究者内化 > 框架外挂，但前者要 350 条轨迹教材、后者零先验冷启动）。
- **#103 Resolution**：金子⑤（工具调用密度=能力分水岭）与「proposer 写得出、selector 认不出」互补——此处是「executor 做不做得动」维度。
- **姊妹库 data-mixture-insights**：金子①②③（记忆生死件/红黑成本分离=粗筛-短训同构/池外扩维度）+金子④（泄漏三层协议）已追注接口文档。

## 6 诚实边界
总分仍**低于人类 instruct 参照 15.7 点**（31.17 vs 46.91，只有 GPQA 单项反超）——「接近专家策展」只在个别能力成立；主表单运行无 std（同 #151/#152 打折纪律）；MLE-Bench Lite 任务规模小（Kaggle 级）；PostTrainBench 目标=1.7B base（post-training 小尺度——**不推翻中训练空位判读**）；12h/任务预算口径；v2 无 venue；GPT-5.4 骨架失败未深挖（只归因工具调用数）。
