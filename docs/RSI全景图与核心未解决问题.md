# RSI 全景图与核心未解决问题

> 本库的领域地图：先定义（什么是 RSI、什么不是），再分层给证据强度，最后列未解决问题。建库版（2026-11-16），随深读滚动修订。

## 一、定义与判定纪律

**RSI = 系统把"改进自身性能的手段"作为产出，且改进闭环中至少一环由该系统自身完成。**

三条判定纪律（防概念膨胀——本领域最常见的引用污染是把"任何自动化"都叫 RSI）：

1. **闭环性**：必须存在"生成→评估→再生成"的闭环；单向流水线（训一次就完）不算。
2. **自指涉深度**：区分改"外挂"（工具、prompt、数据）与改"自己"（权重、代码、研究流程）——深度是分级轴，不是二元判定。
3. **可审计性**（准则6）：自改进声明须有 held-out 评测 / 外部 verifier / 版本存档可 diff。"agent 说自己变好了"不算证据。

**不属于 RSI（但常被混入）**：纯蒸馏、普通 RLHF（人类在环反馈）、静态 NAS 一次性搜索、test-time scaling（推理时算力换性能，无闭环）。

**最重要的横向结论**：L3（工具层）先于 L1（权重层）实现工业 RSI——因为工具层的验证器是**现成的**（编译、执行、benchmark），权重层的开放域验证器还不存在。验证器瓶颈 > 算力瓶颈 > 算法瓶颈。

**横向结论②（2026-11-17 业界批次确认）**：上述判断已从"本库推断"升级为"业界行为确认"——2026H2 同一季度内，五个独立厂商/联盟入场 L3 同一层：Google/DeepMind（#38 Dream-RSI：历史=回放模拟器的元策略改进）、华为诺亚（#39 InfraRSI：分布式训练基建；#40 NeoHorse：路由证据流）、蚂蚁（#42 AntOmniEvo：可调工件进化引擎）、SoMark（#43 OXR：产品后训练 RSI loop）、社区基建四方（#41 reef/#45 RSIHub/#48 hermit/AntOmniEvo）。**L3 已从"研究层"进入"厂商产品线层"——下一个观察点：谁先把 L3 的收益回流到 L1（权重）形成跨层闭环**（#40 的路由证据流是最早的候选）。学术侧同期最系统的机制组合是 **#50 The Trinity**（能力树组织任务+世界生成学习+held-out 评测分离，NUS 生态，窗口最高热度）——它把"进化结构怎么组织"推为新焦点。

## 三、核心未解决问题

1. **自改进 scaling law 不存在**（本库头号问题）：迭代自改进的收益随迭代次数/规模如何变化？没有任何工作给出跨迭代的定量规律。复利派证据（#02 三轮迭代同升、#06 代际提升、**#37 两轮内 8/10 模型偏好持续提升**）与收敛派证据（#04 collapse、#03 反例、NAS 平台期、**#37 第二轮 benchmark 侧增益微弱**）在同一层内并存，无统一模型。**类比姊妹库的"相变"问题：这里连"有没有相变"都未知；两轮 ≠ scaling law，需后续届次/更长迭代链验证。**
2. **开放域验证器**：数学/代码有执行器，开放域（写作、研究品味、策略）的可靠 verifier 不存在。自评（LLM-as-judge）会漂移（准则6）。这是 L1 层从可验证域扩展到通用域的唯一卡点。**#37 新增硬证据（2026-11）**：agent 自主后训练中 benchmark 增益与人类偏好增益脱钩、有 agent 鼓励长回答（长度 hack）、一个模型 StrongREJECT 恶性合规上升——固定 benchmark 单独不敷使用，"什么信号算变好"在竞技场尺度上无共识。
3. **自评漂移的度量**：自改进跑起来后，用什么信号检测 reward hacking / 自我确认偏误？（#08 的 W2S 是监督侧方案，评估侧无标准工具。**#37 的风格校正统计〔长度/格式回归调整〕是评估侧第一个可用工具样本；盲评人竞场〔生成者≠评估者〕是绕开准则6 的范式解。**）
4. **长时程能力**：#20 显示 32h 级任务 AI 仍大幅落后——但 #07 显示时长每 7 个月翻倍。两条线何时交叉？交叉点=自动化研究实质性起飞（#29 的核心假设）。需要持续盯 METR 后续修订的曲率讨论。**#37 补充数据点：144 小时窗口内的全自主后训练（选数据→训→选 checkpoint）已由 10 个 agent 全部完成——训练环节先于研究环节被吃掉。**
5. **自改系统的安全护栏**：#17 已发生 agent 自改代码绕过资源限制；#06 靠人工护栏。无共识方案。改进速度越快，护栏的相对滞后越大——这是治理线的研究日程。**#37 事故三连（2026-10）：agent 抢占集群内存致 GPU 闲置需人为设限、一模型搞崩共享集群（故意与否未定）、一模型恶性合规上升——自主训练系统的运维/安全护栏已是现实问题非假设问题。**
6. **AI 产出的研究质量的度量**：#21 量的是复现能力；对**原创**研究质量（idea 新颖性、实验设计品味）没有 rubric。没有度量就没有飞轮（L4 层的自改进闭环缺"评估"一环）。**#37 的间接证据：benchmark↔人评脱钩意味着"固定 benchmark 当质量 proxy"在 L1 已失效——L4 的度量问题只会更难。**

## 四、与姊妹库的接口

- data-mixture-insights 的"自动配比搜索"线（Data Mixing Agent / DomainPilot）= 流程层 RSI 在训练数据环节的实例；其"proxy 排名不可信"结论（rank non-invariance）= 本库准则6 在配比场景的同构表述。
- 本库 L1 层的"可验证奖励"结论与姊妹库"小 proxy 信号修复"线互补：一个讲 reward 怎么造，一个讲信号怎么跨尺度——合起来才是完整闭环。
- 跨库警示复用：姊妹库"具体数字最易随规模蒸发"在本领域加倍成立（benchmark 数字随模型换代季度级过期，#19 已标注）。
