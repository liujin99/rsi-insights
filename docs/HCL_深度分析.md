# HCL（Harness Continual Learning）深度分析

**总表条目**：#68｜arXiv 2608.19013（v1 2026.08.19 / v2 09.30）｜T2（维持，不升 [高价值]）｜深读批次⑥（2026-11-17，全文）

**【一句话】**把"持续学习"从参数层**平移并形式化到 harness 层**：冻结模型下四组件联合版本化状态+**受保护进化**（Continual Optimizer 提案→Continual Evaluator 过"当前改进 δ/历史保持 ε/有效性"三门才提交），**首次定量测出 harness-level forgetting 并给出单旋钮可控的 stability-plasticity 权衡**（两变体只差 ε：62.98/遗忘 10.94% vs 61.74/遗忘 2.64%）。

## 2 问题设定（3.1-3.2）
- 定义：顺序更新部署中 harness 以获得新行为、同时保留更新前可靠行为（正确响应/合法工具调用/满足环境目标的动作轨迹）；保留=后续更新后在**同输入同执行条件**下仍成功。
- **四组件=可版本化状态**（4）：Task Interface（原始交互→任务输入/目标/约束的结构化表示；prompt/模板/解析规则随版本演进）/Experience Memory（Raw=按任务固定容量保成功证据与失败；Abstract=输出约定/可靠推理模式/避错——跨任务迁移）/Capability Map（**Outer**=API/检索/计算器等外部能力，**Inner**=从经验抽象出的可执行技能——带输入输出步骤与适用域）/Adaptive Router（检索经验+选能力+组装执行上下文）。诚实注：四分解"不是新的 agent 系统分解"，是**把复发执行功能收进可版本化可评估的状态**。

## 3 受保护进化（3.3）
- **Continual Optimizer**：从交互证据诊断哪些组件内容可解释观测结果并提案修订；多组件时**顺序逐组件搜索**（其余状态固定，组件内最多 N 个候选取最高分作为下一组件基底；全不过门则该组件不动）——**部署态在搜索期间永不修改**。
- **Continual Evaluator 三门**（形式化）：① 当前改进≥δ（验证用例）；② **历史损失≤ε——锚点集**：仅评测可用（执行与候选生成均不可见）、LLM 选择器按预测/正确性/格式合规/任务元数据挑（优先失败/格式违规/脆弱/代表性样例，确定性兜底+去重+按任务固定容量），**历史锚在后续任务优化期间保持固定**；历史损失=被当前 harness 解出但候选下失败的锚数；③ 有效性（语法/输出模式/工具使用/任务/环境约束）。多候选过门→取当前任务性能最高、ε 回归小者优先；**全不过门→不更新**。
- **3.4 CL 字典翻译表**（系统级映射，库引用价值高）：Experience Memory↔**replay**；Capability Map↔**表征方法**；Adaptive Router↔**架构方法**；Optimizer+Evaluator↔**优化+正则**——四种 CL 策略的功能被整合进单一演化 harness 的同一"获取-保持"目标。

## 4 实验
- **ALFWorld**（冻结 Qwen3.5-9B，六类别，10 训练 episode/类，134 官方评测）：Static 47.12/RAG 55.56/MemP 53.15/MemRL 60.68（最强非 HCL）/ **Stability-HCL 61.74（遗忘 2.64%）**/ **Plasticity-HCL 62.98（遗忘 10.94%）**——两变体只差 ε，**trade-off 被单旋钮直接控制**；Two-object 组 100%（MemRL 仅 41.18）=组合复用优势；**诚实负例：Cool 组 MemRL 57.14 反超两 HCL（28.60/19.00）**——"任务特定行为或更受益于情景记忆，harness 级更新引入任务依赖干扰"。
- **Minecraft**（deepseek-v4-flash，50 任务课程）：Static 15/50 后平台；Plasticity-HCL **全 50 完成**；动作数 83＜MemRL 88＜MemP 91（更少冗余执行）。
- **受控文本流**（MuSiQue→ProofWriter→GSM8K→HotpotQA，DeepSeek-V4.1-Flash，250 适应+50 验证+**500 不相交测试**/任务）：Plasticity-HCL 76.10（GSM8K 65.2→**96.0**）遗忘 0.40%；Stability 70.65/0.27%。
- **受控多模态流**（检测→字幕→grounding→VQAv2，Qwen3.6-27B）：Stability-HCL 68.92/遗忘 0.22% 最佳平衡。
- **ε 扫描（4.3 Table 3）**：遗忘 0.39%→1.22%→2.00%→3.45% 四档，最终均值 61.25/63.46/62.04/60.13——**有限容忍最好、过度放松精度保持双输**（非单调）；诚实注："预算约束的是抽样锚而非全历史测试例，不保证零测试遗忘"。
- **Opt-HCL（4.3 金子）**：Qwen3-4B 全程 35.10% vs **Qwen3.6-27B 只做候选生成（4B 在线执行）45.75%（+10.65）且在线延迟不变（9.72 vs 9.95s）** vs 27B 在线操作 44.80% 但延迟 39.31s（4×）——**"强模型经持久 harness 更新蒸馏、在线不用强模型"**=#64 生成器/执行器解耦的受控定量版（连 #67 Opus evolver+Sonnet solver 同构）。
- **消融（Table 4，多模态流 Qwen3.5-4B）**：冻结 Memory 更新伤害最大（62.28+遗忘升至 0.83%）；诚实注："部分受限变体遗忘更低是因为新能力获取也更少——**遗忘须与能力获取联读，不能孤立解读**"。
- **报告纪律（C.4）**：验证用例与历史锚**从不用于最终报告**，主分数全用不相交测试集。

## 5 诚实边界
- **交互环境（ALFWorld/Minecraft）回放会改变环境状态→三门中的历史回测退化为 LLM 裁判**（按历史任务记录判候选接受）——锚机制只在文本/多模态流严格生效（门控强度的域依赖，v2 自述）。
- 遗忘量级本身小（文本/多模态 0.2-3.5%）——现象可测且可控，但"灾难性"程度远小于参数 CL 文献；ALFWorld 遗忘 10.94% 是最大读数。
- 无独立 Limitations 节；诚实性靠内联注（Cool 负例/锚抽样/遗忘联读）。
- 模型版本谱杂（Qwen3-4B/3.5-4B/3.5-9B/3.6-27B、DeepSeek-V4-Flash/V4.1-Flash 分散于各表）——跨表可比性打折。

## 6 库内连线
- **Q1**：与 #67 构成收敛侧对偶——#67 说"不进化是贬值"（漂移侧），#68 说"乱进化是破坏"（更新侧）；**ε 旋钮=复利/遗忘权衡的第一个可调参数化**；两篇合读=harness 层"复利动态修正观"完整闭环（累积、贬值、遗忘、守护四机制全齐）。
- **Q3**：锚点集=**纯 harness 层的 replay 机制**（评测专用、对执行与生成双盲、跨任务冻结）——可移植的工程件；三门提交连 #39 复跑验证/#50 hash 账本/#66 验证门（四例同簇，准则6 的提交层执行家族）。
- **Opt-HCL 连 #64/#67**："改进冻结在 harness、在线执行换便宜模型"三作同向——**harness=持久化的知识载体**，强模型一次性出场。
- 3.4 字典表=引用 CL 文献时的标准翻译层。

## 7 裁定与遗留
- **裁定**：T2 维持不升——问题命名+形式化+单旋钮受控权衡 T1 级；但读数量级小、域窄（两交互环境+两受控流）、交互域门控退化、模型版本谱杂；**作为 Q1 对偶件与 #67 配对引用价值最高**。
- 遗留：① 锚点集大小/选择偏差对 ε 门实际弹性的影响未量化；② ALFWorld LLM 裁判版三门 vs 严格回放的差距未对照；③ 遗忘量级小是否因为任务流太短（500 测试/任务）；④ #66 附录 A 表内 11 系统与本文字典表的合并去重（子域系统名录工程）；⑤ 与 Karten et al. "Continual Harness" 的实证对照（AAH 表内第二名 vs 本文未互引——撞名双作的正面对决未发生）。
