# Blind to What They Can Fix（程序型 RSI 的检测缺口）深度分析

**总表条目**：#157｜arXiv 2611.29807（v1 2026-11-22）｜T2 **[高价值]**（轻评估⑧→**深读坐实**）｜深读批次㉒（2026-11-25，全文 HTML+附录；与 #154 配对=「修得了 vs 看得见」双证）

**【一句话】**程序型 RSI 的**检测缺口命名+归因+成本账**：agent 把任务程序改进到高分，但部署环境一变，**被明确要求写下的运行时检查在 4/5 域里对一半以上失败保持沉默**（Codex：Seaquest 52%/Kangaroo 55%/服务调度 64%/AppWorld 89%；三个开源模型 82%）——而失败既可检测（正常运行记录建的通用 monitor 在 3 域漏 5-18%；**32 条随机记录关系就消掉大部分漏报**）也可修理（**被叫回时同一 agent 修好九成以上**，Seaquest 修后保 81% vs 修前 5%）；根因=**检查覆盖**（检查只看机制假设、不看记录里揭示失败的关系）+**目的缺位**（告知「检查是唯一叫你回来的东西」后 Codex 漏报 69%→6%、95%→0%，**开源三模型仍漏 84-100%**）；部署重放的成本账：**完美修理员躲在自家检查后面只多 0.01-0.03**——瓶颈在触发不在修理。结论：**「能力（competence）与自维护（self-maintenance）是系统的两种不同性质」**，评自改进必须把「检测率」与「分数」并列报告。

## 1 出处与身份
- **3 人（坐实）**：Teng Cao/Yu Deng/**Kristian Kersting**——**TU Darmstadt AI/ML Lab+hessian.AI**（与 #162 MGM 同用 hessian.AI 算力——德国 RSI 学术簇成形）；共同一作。
- **预注册纪律**：**120 条书面预注册预测：69 中/36 败/14 未定**——含「Codex 知情后漏报会持续」的预测**失败**（知情干预比预期更有效）也照记；AppWorld 两项失败标准因产生失败太少而事后修改并**重新注册+16 程序复现**。
- **方法学定位**：软件测试的**变异分析（mutation analysis）应用于环境而非程序**（改变=环境正则的受控变异）；「checked coverage」（检查覆盖）借用软件测试概念；知情 Codex 的交叉检查=蜕变关系（metamorphic relations）；underd. 评估框架三量同测：任务分/检测/修理在**同一失败集**上。
- **发现路径**：补扫③→轻评估⑧ [高价值]→推荐顺位③→用户裁定「继续」。

## 2 机制（§3——受控变化+三量框架）
- **失败集构造**：环境 E₀ 的正则被干预 δ 改变（动作效果/资源负载/观测延迟/API 语义）——**盲变**（绝大多数变化由未见程序与结果的隔离会话所写）；变化仅当任务仍可完成时保留（参考解或独立成功运行证实）；任务失败=变化后均分 < 原来一半（阈值 0.3/0.7 稳健性检查）。
- **三量定义**：检测=检查/监控在 ≥半数 episodes 报警（同一执行记录喂所有检测器、永不告知是否变化）；修理=同一作者 agent 每个失败一节会话（固定工具预算、**不告知改了什么**），修后独立评测复分；**检测缺口 G=漏报且可修的失败份额**。
- **五域×最多七作者模型**：Seaquest/Kangaroo（街机）/Craftax（生存游戏）/服务自动扩缩（16 小时达标 15）/**AppWorld**（独立维护的 API 套件、整份日报全对才算成功）；主力=Codex（gpt-6.1-sol），Claude opus-5.5+五个开源（Kimi-K2.6/Qwen3.8-27B/Flash/Mistral-Medium-3.5/gemma-4-31B）做部分复现；改进后的程序确实是高分（Codex 每集 1.9 次救援 vs 改进前 0；服务调度 15/16 小时 vs 手写阈值策略 15.6）。
- **检查协议**：指示明确要求「规则依赖什么（成本/速度/不受影响之物）就写成假设+逐步检查」+「从未被违反的假设不提供信息」；矛盾 ≥3 次且多于确证=检查坏了→报警。

## 3 主结果核验（§4 四问逐行）
- **Q1 高分不附带会报警的检查**：Codex 检查漏 52/55/64/89%（四域；Craftax 例外全中）；六模型合漏 65%（服务）；三开源合漏 82%（AppWorld）；**连续三代改进程序漏报 95%→79%→64%**（改进只部分帮助）；**任何报警阈值都不能把检查变成可用警报**。域外检测器好得多：**结果规则（一行代码：成功数掉一半就报警）漏 7/9/8%** 且误报 ≤5%——**「被明确要求写的检查不如一条结果规则」**；通用 monitor（正常 20 集参考学通用统计范围）漏 5/18/0% 但对「程序仍正常的变化」误报 52-69%（对任何变化都反应）；按需 monitor 漏 25% 居中。**Codex 事后看得见**：给无标签部署记录，120/120 失败集说环境变了、0/未变；94% 失败集判程序失败 vs 9% 无害变化——**信息在记录里、检查只是不看**。
- **Q2 修得了**：Codex 被叫回（无提示）修好 69/77（Seaquest）+37/37（服务）+55/55（AppWorld）漏报失败；修后程序保 81% 原性能（vs 修前 5%）；**G=48%/64%/89%**（漏报且可修）；修理成功率与「检查是否报过警」「会话带不带运行报告/一比特警报/什么都不带」无关；Qwen3.8-27B 同型（65%）；两个弱模型只在 AppWorld 行（服务域修理失败）。
- **Q3 归因=覆盖**：固定程序只改检查内容——信息性关系（需知道变化）把漏报 52%→4%（Seaquest）/65%→4%（服务）/48%→20%（Kangaroo）；**无关关系不帮忙（50/63/48%）**；**32 条随机关系：4%/4%/15%**（不需要知道变化、只要广）；改进警报规则无效（对检查判定频次学范围仍漏 61%），但**记录「检查多久适用一次」（检查从不看的量）**降到 15%；**知情段落**（声明检查目的）：Codex 69%→6%（16 个程序全部加了「救援在时间预算内持续发生」的进度检查——标准程序无一有此）/95%→0%（交叉核对独立 API 调用），**开源三模型 84%/87%/100% 纹丝不动**；要求「广覆盖」反噬（漏 0% 但未变日误报 99.8%）；给失败示例只小帮（28%→19%）。
- **Q4 成本账（部署重放）**：从不叫回=0.35/0.37（十日值）；自家检查=0.46/0.56；按需 monitor 0.79/0.83；通用 monitor 0.81/0.83；变化当天叫=0.86/0.83；**换完美修理员但留在自家检查后面=+0.01/+0.03**；知情 Codex 自家检查=0.90（=完美时机）；**简单规则（成功减半报警）=0.82**；session 有成本时通用 monitor 直到 3.7 天/次仍占优；弱模型 monitor 只抬 0.38→0.46/0.47（**修理不行时触发白搭**）——**检测上限=修理能力，两量必须分开测**。

## 4 深读金子（摘要外）
- **金子① 「选择指标决定产出性质」（结构性洞察）**：**「改进环里没有任何东西测量或奖励检查的可靠性」**——版本只按任务分留存，所以高分程序自带高分盲的检查。连 #103 的域外预言在监控层复现（选择度量外的性质不被建设）；连 underspecification 文献（D'Amour 2022：同分程序部署后行为不同）。
- **金子② 「修得了」与「看得见」的分离定理（Q2+Q4 合读）**：同一 agent、同一失败——被叫回修 9 成+、自己发现 1-5 成；**部署价值被触发而非修理限制**（完美修理员只多 0.01-0.03）。**「能力」与「自维护」是两种性质**——评自改进只报分数=漏掉半个系统。
- **金子③ 32 条随机关系=覆盖的暴力证明**：不需要知道变化、只要检查「看」得够广，大部分漏报消失——**检测缺口的本质是检查太窄不是失败太难**；同时「广覆盖要求」反噬（99.8% 误报）=**广度必须配正常范围基线**（参考 episodes 学范围）——监控设计的双变量律。
- **金子④ 知情段落的模型分层（开源-闭源差距的新读数）**：一句目的声明让 Codex 漏报 69→6/95→0，三个开源模型纹丝不动（84-100%）——**闭源前沿把「理解检查目的」内化、开源模型只跟随指令字面**；且团队预注册了「会持续」的预测并**诚实记录预测失败**（连 #104 Claude API 拒答的对照面：能力分层不只安全策略、还在目的理解）。
- **金子⑤ 评测学处方（可直接入 Q6 工具箱）**：「评自改进系统应随分数报告：**诱导失败的自我报告率+未变运行误报率+无害变化误报率**」+变异分析应用于环境的整套协议（盲变+可完成性守门+同一失败集三量同测）——**给「验证信号家族」加了一个可操作的二元分类器**（修得了但看不见的系统≠改进中的系统）。
- **金子⑥ AppWorld 的不可观测结局域**：程序不能观测自己的报告对错（无结果可用）→结果规则失效、通用 monitor 漏 61%——**知情 Codex 用蜕变式交叉检查（同一信息问两个独立 API）补位**：**「结局不可观测时，检测=冗余请求的交叉验证」**（连 #158 DoppelVet 行为对照：一个是更新前的验收、一个是部署中的监控）。
- **金子⑦ 抽查式诚实披露**：五条限制全列（检查只在要求格式里存在/Seaquest 外程序少+区间下探 40/44/8%——**「一半以上」的联合重采样结论主要靠 AppWorld 下界 73% 立住**/覆盖实验证明「记录里有信号」而非「agent 找得到」/重放最多一次调用/通用 monitor 有参考数据优势）——**结论强度分层诚实**。

## 5 库内连线
- **#103 Resolution Hypothesis**：检测缺口=识别瓶颈的**运行时监控层**形态（金子①：选择度量外性质不被建设——#103「方法级」结论在程序级复现）；**与 #154 Self-WSP 同周配对**：Self-WSP=外环能选但模型不懂、Blind=模型能修但检查看不见——**「选择/修理能力」与「理解/察觉能力」在两个域里被拆开**。
- **#157↔#158 DoppelVet**：一体两面——DoppelVet 管**更新入档前的验收**（证据等价类→行为对照）、Blind 管**部署后的持续监控**（覆盖+目的声明）；两者共同构成「自维护」的入档/在岗两道门。
- **#105 AdaObs**：知情段落=观测目的的显式化（「考卷不变、显微镜变」的监控版）；L1 式关系添加=观测覆盖细化。
- **#91 PACE/#53**：金子①=「分数涨就留存」的检查版（留存度量外无检查质量的信号）；变异分析+预注册=验收纪律的新工具。
- **#102/#156 权重自改线**：Q4 的「检测上限=修理能力」与 Self-Upgrading 的 self-examiner（自己考自己）同题——**自维护要内建成环的一环**（改进环里必须有一量测检查/检测可靠性，否则按定义退化）。
- **#162 MGM（同 hessian.AI 簇）**：MGM 失败池=把评测预算花在暴露弱点处；Blind 金子③=把检查覆盖花在记录关系上——**「预算给诊断信息量」的两兄弟**。
- **#41 reef**：变异分析应用于环境的整套协议=基建审计的方法学亲戚（结构化造假检查）。

## 6 诚实边界
Seaquest 外独立程序少（联合区间下探——「一半以上」主要在 AppWorld 稳）；覆盖实验证明信号存在而非 agent 能找到；部署重放≤一次调用+录制会话；通用 monitor 有参考 episodes 优势+Seaquest 上开发+对无害变化过度反应+在 AppWorld/Craftax 失效；检查只存在于被要求写的格式里；未测试「按检测能力选版本的改进环」（金子①的正面实验缺位）；五域全小规模（程序 3-20 个/域）；无 venue、v1；预注册预测 36/120 败（诚实但=预测能力一般）。

## 7 遗留（深读新设）
- 「按检测率选版本」的改进环正面实验（金子① 的解法检验——预期与分数选择冲突时谁赢）。
- 知情效应在更多域/更多模型上的复现（三开源模型是否能力上限还是对齐问题）。
- 无害变化与有害变化的区分（通用 monitor 的 52-69% 误报何时可接受——session 成本线 3.7 天的域外换算）。
- 蜕变式交叉检查的成本账（冗余 API 调用的开销 vs 检测增益）。
- 与 #158 的合并读：入档验收+在岗监控的统一「自维护框架」。
