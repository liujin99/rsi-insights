# Gödel Forest（数据配方 RSI 的深挖-广搜平衡）深度分析

**总表条目**：#151｜arXiv 2609.36675（v1 2026-09-29）｜T2 **[高价值]**（引用链补扫→**用户点名深读坐实**）｜深读批次⑯（2026-11-24，全文 HTML）

**【一句话】****把「验证太贵→深挖还是广搜」这个数据配方 RSI 的结构性困境做成了正面设计题**：单个 agent 深挖会死在窄路上、朴素并行会重复踩同一个坑、互传原始 trace 会撑爆上下文——Gödel Forest 用「每棵树私有持久化假设树（深）+共享进化记忆（广）」拆解：树间不传数据不传日志、只传 **~100 token 的结构化教训**（试了什么/分数动了多少/为什么/下次怎么办），配全局 leaderboard；RSIBench-Data 六基准平均 **+10.70%**（SWE-bench Verified 35.00→54.00），共享记忆消融 **+7.00%**（vs 三个不通信的并行 agent）。

## 2 机制（§3 两层结构）
- **单树四阶段循环（深）**：每 worker i 私有树 T^(i)+证据台账 H^(i)：① **Diagnose**——分析上一批候选模型的失败模式（runaway completion/ungrounded actions/skipped verification 等）；② **Propose**——选父节点、生成子代程序（=可执行的数据合成/策展代码），条件于私有台账+共享记忆；③ **Validate & Evaluate**——**诊断门控**：先在自选的轻量诊断子集 B^diag 上评，过门槛才用同一 checkpoint 评全集（不过=早停剪枝、省评测预算）；④ **Review**——记录证据、决定深挖/调参/回溯祖先节点。
- **森林共享记忆 M=(Λ, L)（广）**：Λ=全局 leaderboard（所有已全评 agent 的效用，透明锚点）；L=**结构化教训** ℓ=⟨intent（试的假设），ΔU（分数变动），Attribution（因果诊断），ρ（可操作规则）⟩，**~100 token/条**——刻意不传原始数据/trace（对比 MGM 的 trace 交换=context 饱和）。
- **Read-Evolve-Publish 异步协议**：拉取式、无全局同步屏障——负面教训=归纳护栏（别的方向踩过的坑直接剪枝）、正面教训=催化种子（邻树开新分支）；终止返回 leaderboard 最优 checkpoint。
- **预算**：16h 墙钟+$500 Tinker 累计预算/森林；目标模型 Qwen3.5-35B-A3B-Base+LoRA SFT（共享 Tinker 后端）；Claude Opus 4.8=固定外部 rollout 生成器（worker agent 为 Claude Code+Sonnet-5 或 Codex gpt-5.6-sol）。

## 3 主结果核验（Table 1 + 消融逐行）
- **六基准（RSIBench-Data；vanilla Claude Code vs Gödel Forest K=3；官方分 S_off）**：SWE-bench Verified **35.00%→54.00%（+19.00）**/SWE Multilingual 22.00→30.00/SWE Pro 4.00→15.00/Terminal-Bench 2.0 5.62→17.98/GPQA Diamond 52.00→55.00/AIME 2026 49.17→60.00——**平均 +10.70%**，六个全升。
- **效率悖论**：墙钟 5/6 更快（14.91→14.06/14.20→11.02/9.54→7.49/8.87→15.50 反例/6.43→5.76/9.29→8.61）；但**累计花费在长程基准更高**（SWE Pro 45.63→419.87）——论文解释：弱基线崩溃/循环/提前退出截断轨迹，进化模型持续多轮推理所以花得多（成本高=能力产物而非搜索浪费；TB 2.0 的 295.06 vs 156.93 同型）。
- **跨底座（Codex gpt-5.6-sol）**：SWE-V 33.00→44.00（+11.00）/TB 20.22→23.60（+3.38）——增益不锁死在单一 worker 底座。
- **K 消融（SWE-V，共享记忆全开）**：K=1 45.00/K=2 51.00/**K=3 54.00**/K=4 54.00 平台且墙钟 15.80h+花费 $404.43——**固定预算下并发把算力劈碎、深度下降**。
- **协同 vs 无协调消融（本批最值钱的对照）**：3 独立并行（无共享记忆）=47.00%，Gödel Forest K=3=54.00%——**共享记忆贡献 +7.00%**（可对比预算 $421.63/13.38h——省的是重复踩坑的训练）。

## 4 深读金子（摘要外）
- **金子① 深/广困境的三败法陈述（§1/§3.1）**：验证一个数据假设=完整训练+评测（training-in-the-loop 瓶颈）→ 单树深挖=path-dependent 停滞；朴素并行=重复浪费在同款失败；重 trace 共享=context 饱和不 scale。**这是「验证器瓶颈」的成本版的结构化表述，比摘要级判读更精确**：它不是「没人想到并行」，是并行的协调本身有三种死法——深、广、协调三轴都得付代价（连 #103：广度=廉价生成更多候选，分辨好坏仍卡验证；Gödel Forest 的共享教训=用社会化的软选择绕开一部分验证成本）。
- **金子② K=3 最优、K=4 归零（深度-广度的量化兑换）**：K=3→54.00、K=4→54.00 但更贵更慢——**固定预算下广度的边际增益在第三个并发后归零，单价=单树深度**。对姊妹库：并行配方实验不是越多越好，存在递减点（本文设置下=3；换算到中训练要按预算结构重估）。
- **金子③ 蒸馏教训>原始 trace（协调带宽的设计读数）**：~100 token 结构化 lesson（intent/ΔU/Attribution/rule）+leaderboard=异步黑板——**47.00→54.00 全部来自这层轻协调**。对姊妹库：实验教训的**结构化沉淀**（每次配比实验记假设/Δ分/归因/规则四元组）是有实测溢价的协作原语，比共享原始日志便宜两个量级且无 context 代价。
- **金子④ 两条教训案例=监督位选择的第三标本（§4.5 微观案例）**：**Lesson #1**——全轮 dense 监督教坏终止（模型停不下来，0/9、0/10）→「loss mask 只到最后一个 assistant turn」恢复终止边界（46%）；邻树读到后采用，0→22%（一传就灵）。**Lesson #2**——最后轮监督又丢了中间验证动作（bash 测试没 loss）→ prefix-truncated 轨迹把中间命令转成伪终止目标→峰值 **55%**（选中 checkpoint）。**连 #100 RSI-Prime 决策级屏蔽（准则>数量）与 #02 loss 脱钩：监督哪个位置（轮/动作）本身就是数据配方变量，且「教训」形态可跨 worker 迁移**——这是把 #100 的监督位读数从单模型推广到多 agent 协同的桥。
- **金子⑤ 非单调轨迹+存档解耦（§4.5 宏观）**：高性能 checkpoint 后常跟大幅下跌（激进数据混合/新监督格式）——**全局存档把「探索失败」与「选择最优」解耦**，临时失败不没收历史峰值（连 #53 撤走纪律/#91 PACE acceptor：探索归探索、算数归算数）。
- **金子⑥ 诊断门控=评测预算的分级消耗**：B^diag（worker 自选组成）→门限→全集——评测成本侧的结构化省法（与 #62 训练预算结构化同层；对姊妹库=「代理粗筛→确认」两级评测的 post-training 版）。
